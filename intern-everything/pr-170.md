# PR #170 description

# Intern everything: 4-byte handles for the index engine's interned data

## Why

The index engine's Datalog relations spent most of their memory on wide handles
to interned values. On glxy, peak RSS was 3.7 GB, and the `locals` store alone
held 83.1M rows in 2.04 GB. Each row's leaf is `(Path, FormalIndex, Path)`, so
the width of `Path` dominated.

| Type | Handle on `main` | Handle now |
|---|---|---|
| `Path` | 8 B pointer (`tailshare::Seq`) | 4 B |
| `Str` (and `Function`, `Label`) | 8 B `u64` id | 4 B |
| `CallTargetObject` | 24 B enum of `FunctionId` or `ArcIntern<str>` | 4 B |
| `CallDispatchKey` | 40 B enum of up to two `ArcIntern<str>` | 4 B |
| `DecisionSet` | 24 B (`&'static [DecisionId]` plus a `collapse` flag) | 4 B |

Each handle is `Copy`, `Option` of it is also 4 bytes, and cloning one touches
no reference count.

The idea came from the interned `PathId`s on the `ctadl-access-tree` branch. The
interner is a new design. It borrows from both that branch's `concurrent.rs` and
the `immortal` crate, and uses fewer bytes per entry than either.

## Results

Peak memory, `main` → this branch:

| Benchmark, engine | Peak (GiB) | Wall time |
|---|---|---|
| glxy, serial | 4.57 → 2.57 | no change |
| glxy, par | 4.75 → 2.77 | +1.6%, within noise |
| glxy, lsm | 0.42 → 0.29 | +4.3% on quiet runs |
| xbot, serial / par / lsm | 1.09 / 1.28 / 0.81 → 0.80 / 0.93 / 0.56 | faster |
| udpbus, serial | 44.9 → 26 | +5.2% |
| udpbus, par | 49.2 → 28 | +7.4% |

- On glxy, the `locals` store fell from 2.61 to 1.41 GB, and peak RSS fell by
  2.1 GB.
- udpbus with lsm wasn't measured: on `main` it doesn't reach a fixpoint within
  an hour.
- Every derived relation is the same set as on `main`, checked with
  `scripts/fact-dump-diff.sh` on glxy and xbot (udpbus is too large to dump).
  `cargo xtask regression` results are unchanged. The one exception is described
  under "xbot".
- serial, par and lsm all build and pass every test.

**Open performance work.** The goal was at most 5% more wall time on any engine.
udpbus misses it:
- udpbus serial retires 8.7% more instructions than `main`. The extra work
  arrived with the frozen path set.
- About half of udpbus par's slowdown arrived with the `DecisionSet` change.
- glxy lsm spends 4.2% more cycles, mostly in the `edge_split ⋈ locals` rule,
  which the path-set change rewrote.

## Design

### The interner: `immortal::id` (`IdInterner`, `id_handle!`)

`IdInterner<T>` maps each distinct value to a 4-byte `Id` (a `NonZeroU32`) and
back. Values are never freed.

- **Shards.** `S` shards, a power of two, 256 by default. Each shard is an
  `RwLock` over a `hashbrown::HashTable<u64>`, padded to a 128-byte cache line,
  plus its own append-only arena.
- **Table entries.** Each entry packs `id | hash32 << 32`. The table rehashes
  from the stored half of the hash, so a resize or a tag miss never reads a
  value.
- **Arena.** Buckets of `64 << b` slots, allocated under the shard's write lock.
  The bucket pointers are kept apart from the locks, so a lock-free `get` never
  shares a cache line with a lock word that interning writes.
- **Ids.** An id is `((local + 1) << log2 S) | shard`. A shard that runs out of
  ids panics and names the handle type; ids are never truncated.
- **Unsized values.** `str` and `[T]` go in a per-shard bump arena, so a value
  costs no malloc block of its own.
- **Soundness.** `get` reads a slot without a lock. That is sound because a
  handle can't be forged: there is one interner per brand type, and every `Id`
  comes from `intern`, `try_get` or the checked `from_raw`. The `id_handle!`
  macro declares a handle type with its own `static` interner, and handles of
  different types don't mix.
- **Cost.** About 24 bytes per entry at 10M fixed-size keys, against about 110
  for `access-tree`'s `concurrent.rs` and about 38 for `immortal`'s older
  interner. It was also the fastest of the three at 16 threads.

### The handle types (`ctadl-index/src/facts.rs`)

- **`Str`** is an `id_handle!` over `str`. Its serde now writes the string and
  interns it on reading; on `main` it wrote the raw id, which nothing persisted.
- **`CallTargetObject` and `CallDispatchKey`** intern the whole enum value. The
  content types are `CallTargetObjectKind` and `CallDispatchKeyKind`.
  `CallDispatchKey::c()` is interned before the fixpoint, so the rule that
  compares against it interns nothing.
- **`Path`** is a front-cons list of interned `PathNode { head, tail, hash }`.
  - Every suffix of an interned path is itself interned, so taking a path's tail
    is one arena read.
  - `hash` is the suffix hash `mix(head, tail's hash)`. The hash of
    `segments · rest` can therefore be computed from `rest`'s stored hash
    without walking `rest`.
  - The empty path, `Path::EMPTY`, is a compile-time constant whose bits no
    `PathId` can have.
- **`FlowVertex`** gets an explicit zeroed 4-byte pad field, so the LSM
  provider, which stores and compares raw bytes, never reads an uninitialized
  byte.
- **`tailshare`** is deleted, since nothing uses it any more.

### Two phases: seeding, then a fixpoint that interns nothing

An index is built in two phases:
- **Seeding** converts inputs to relations. Interning is allowed here, including
  concurrently.
- **The fixpoint** runs the rules. It never interns a `Path`, `Str`,
  `CallTargetObject` or `CallDispatchKey`, and resolving any of them takes no
  lock. The only values interned mid-run are new `DecisionSet`s, which lattice
  joins create.

A test runs the fixpoint in a child process and asserts that those four
interners don't grow. `profile.json` reports the growth as `fixpoint_interned`.

### The frozen path set (`ctadl-index/src/index_engine/path_set.rs`)

The rules often build a candidate path and keep it only if it is an admissible
path. Most candidates fail: on a dense binary, the engine built four billion
candidate paths and kept six percent of them. On `main`, each one was interned
mid-run, under a shard lock.

`PathSet` is a per-index, read-only table of handles that answers "is
`prefix · [adjust] · rest` a path?" without building the candidate:
1. Fold the new segments onto `rest`'s stored suffix hash, normalizing offsets
   where they meet.
2. Probe the table once.
3. On a hit, confirm it by walking the matched path's new segments and checking
   that the tail where they end is `rest` itself.

This neither interns, allocates nor locks, and costs time in the length of the
new part only. A miss leaves nothing behind.

Seeding precomputes every member's splits (its prefix keys and its
trailing-offset split) and interns the split keys, so the rules look splits up
instead of building them. Every path the rules split is a member, except the
empty path, whose split is answered directly. A split asked of a non-member is
a bug: debug builds panic, and release builds count it in `profile.json`'s
`split_misses`.

The set is per index, not global. The global interner also holds prefix keys,
rests and other indexes' paths, so having a handle isn't the same as being
admissible. The `paths` relation stays, for output. It holds the same set as the
path set by construction, and debug builds assert that at seeding.

### `DecisionSet` (`ctadl-index/src/index_engine/decision.rs`)

- A set is a 4-byte handle into one of two interners, one per kind (exact or
  collapsing). The top bit names the kind, so indexes of both kinds can be
  built side by side in one process, as the tests do.
- The empty set and the two ⊤s are reserved values that neither interner
  issues.
- `Eq` and `Hash` act on the handle. There is no `Ord`: `PartialOrd` and `join`
  remain the lattice order, as on `main`.
- The union cache is keyed by handle pair, in 16-byte seqlock slots. That takes
  about 16 MB instead of about 40 MB.

### Ordering and reproducibility

`Ord` on a handle compares ids, and which id a value gets depends on the order
values were interned in, which varies between processes and under `par`. Each
handle type, and each type that orders by one (`Decision`, `FlowVertex`,
`QueryEndpoint` and others), has a `content_cmp`. Every sort that feeds printed
output uses it: graphviz, the relation dumps, SARIF, the query formatter and
diagnostics.

The query search was the biggest leak: it breaks ties between equal-length
paths by the order of successors, which followed the index's row order.
`TaintSearchGraph::new` now sorts every successor list by content.

`tests/integration/determinism.rs` runs the whole pipeline on a fixture
(`tests/c/ties.c`) in two child processes. One pre-interns the fixture's values
in content order and the other in reverse, and the test asserts that both
render byte-identical graphviz, relation dumps and SARIF.

### LSM storage (`lsm/src/ascent_provider.rs`)

LSM run files hold raw handle bits. They are written and read in the same
process, and interned values are never freed, so the bits stay valid.
- `lsm_col!` now takes each column's field types and checks at compile time
  that their sizes add up to the type's size, so a type with padding is
  rejected.
- In debug builds, `ref_from` asserts that every handle it reads back was
  handed out.

LSM stores every column in whole 8-byte slots, so 4-byte handles don't shrink
its files. The goal there was only not to regress, and lsm memory fell anyway.

### Tooling

- `CTADL_DUMP_RELATIONS=<dir>` makes `ctadl index` write every relation of the
  index engine to `<dir>/<relation>.tsv`, every column by content. It panics if
  a relation is missing from the dump.
- `scripts/fact-dump-diff.sh` records and compares those dumps as sets, between
  two builds or between engines (serial, `-j N`, `--lsm`).
- `profile.json` now reports the `locals` heap report, every interner's entries
  and bytes, the frozen path set's size, `split_misses` and
  `fixpoint_interned`.

## Changes to formats and behaviour

- Parquet, `Display`, `Path::parse` and serde encode every handle by content,
  byte for byte as on `main`. The exception is `Str`'s serde, which writes the
  string instead of a process-local id.
- Writing results interns nothing new. On `main`, the parquet writer interned
  every output path's string.
- Output that used to follow handle or row order is now in content order. Where
  several equal-length traces exist, the query may report a different one than
  `main` did. The one it reports is now the same on every run.

## xbot

xbot isn't deterministic on `main`. Each `context_summary` decision set grows
during the fixpoint, and every intermediate set it passes through leaves rows
in `context_summary_set`, `set_member` and both `set_establishes_*` relations.
How many intermediate sets appear depends on evaluation order. The rules join
those relations against the current `context_summary`, so the stale rows never
reach output. The comparison against `main` accepts differences in those four
relations only.

## Bugs on `main` fixed along the way

- **Union cache.** Its seqlock writer took a slot with an Acquire CAS and then
  stored Relaxed, with no Release fence to pair with the reader's Acquire fence.
  A reader could accept a torn entry.
- **`immortal`'s shard choice.** It sharded on the hash's top 7 bits, the same
  bits hashbrown takes its tags from, so every entry in a shard had the same
  tag. It now shards on the middle bits.
- **Debug logging under `par`.** With debug logging on, `par` panicked
  (`CMap::frozen() on an unfrozen map`) whenever `context_locals` was non-empty.
  The debug-only `dropped_compositions` report probed the contextual `locals`
  store after the fixpoint, when it is left unfrozen. The probe now works in
  either state.

## Accepted costs and non-goals

- **Interned values are never freed.** Path-set by-products such as prefix keys
  and rests, intermediate `DecisionSet`s, and arena slack all live for the whole
  process. Production builds one index per process, so the pool grows across
  indexes only in tests. `profile.json` reports each interner's size, so this
  cost is visible.
- **Several indexes per process.** Tests may build several indexes in parallel.
  Each stays correct and sound. The memory, time and lock-free guarantees are
  only for one index per process.
- **Not attempted:** a 4-byte `FlowVariable` (about 20 rules pack `CallArg`
  variables mid-run, and a handle would turn each into a lookup), packing LSM
  columns, freeing interned values, and changing the rules' semantics.
